# Datasets

This project keeps small sample datasets in git and treats large/generated datasets as local artifacts.

## Repository-tracked sample datasets

### `data/raw/sample_news.csv`

- Purpose: deterministic news input for smoke tests and examples.
- Format: normalized project news schema.
- Columns: `ticker`, `published_date`, `title`, `summary`, `source`, `url`.
- Notes: intentionally tiny; not suitable for performance claims.

### `data/raw/sample_prices.csv`

- Purpose: deterministic OHLCV price input for smoke tests and examples.
- Format: normalized project price schema.
- Notes: intentionally tiny; not suitable for performance claims.

### `data/processed/sample_modeling_dataset.csv`

- Purpose: example output from joining sample news and prices.
- Generated by:

```bash
py -m trading_sentiment.cli build-dataset --news data/raw/sample_news.csv --prices data/raw/sample_prices.csv --output data/processed/sample_modeling_dataset.csv
```

## Recommended first historical dataset

### Alpha Vantage News & Sentiment API

- Why first for the class-project window: it supports bounded news requests by ticker and date, which fits an Oct-Dec 2024 portfolio demo better than Yahoo's recent-news endpoint.
- Access path: request a free API key from Alpha Vantage, then store it outside git as `ALPHA_VANTAGE_API_KEY`.
- Output format: the project normalizes Alpha Vantage articles into `ticker`, `published_date`, `title`, `summary`, `source`, and `url`.
- Limits: free API keys have request limits, and the endpoint caps returned articles. Treat the result as a research sample, not a complete market-news archive.

Recommended command for the Oct-Dec 2024 project window:

```bash
export ALPHA_VANTAGE_API_KEY="your-api-key"
py -m trading_sentiment.cli fetch-alpha-vantage-news \
  --tickers AAPL,MSFT,NVDA,TSLA,AMZN,GOOGL,META \
  --start 2024-10-01 \
  --end 2024-12-31 \
  --output data/raw/news.csv
```

### FNSPID — Financial News and Stock Price Integration Dataset

- Why first: large, historical, and ticker-aligned, which fits this project better than generic market-news corpora.
- Approximate coverage: financial news for thousands of stocks across 1999–2023.
- Access path to investigate/use locally:
  - GitHub: `Zdong104/FNSPID_Financial_News_Dataset`
  - Hugging Face dataset: `Zihan1004/FNSPID`
- Likely column mapping:
  - `Stock_symbol` → `ticker`
  - `Date` → `published_date`
  - `Article_title` → `title`
  - `Url` → `url`
  - publisher/author metadata → `source`
- License note: treat as research/portfolio-only until the dataset license and original-source rights are verified. Do not use for commercial claims without review.

Recommended prepare command after downloading a FNSPID-style CSV locally:

```bash
py -m trading_sentiment.cli prepare-historical-news \
  --input downloads/fnspid_stock_news.csv \
  --output data/raw/news.csv \
  --ticker-column Stock_symbol \
  --date-column Date \
  --title-column Article_title \
  --url-column Url \
  --source-name FNSPID \
  --tickers AAPL,MSFT,NVDA,AMD,GOOGL,META,TSLA \
  --chunk-size 100000 \
  --max-rows 50000
```

If the dataset exposes a direct CSV URL, `--input` can be an HTTPS URL instead of a local file. The command streams chunks and only writes the normalized filtered subset, which helps avoid loading huge datasets into memory.

For very large remote files where normal CSV streaming is too slow, use `sample-remote-news` to scan bounded HTTP byte ranges without downloading the whole file:

```bash
py -m trading_sentiment.cli sample-remote-news \
  --url https://huggingface.co/datasets/Zihan1004/FNSPID/resolve/main/Stock_news/nasdaq_exteral_data.csv \
  --output data/raw/fnspid_sample_news.csv \
  --ticker-column Stock_symbol \
  --date-column Date \
  --title-column Article_title \
  --summary-column Lsa_summary \
  --source-column Publisher \
  --url-column Url \
  --source-name FNSPID \
  --tickers AAPL,MSFT,NVDA \
  --range-bytes 25000000 \
  --step-bytes 25000000 \
  --max-ranges 20 \
  --max-rows 5000
```

`sample-remote-news` is a sampling/extraction helper, not a guaranteed full historical pull. Huge CSV byte ranges can begin or end inside quoted article bodies, so the command keeps complete parseable rows and skips malformed/incomplete fragments. Increase `--max-ranges` or adjust `--start-byte`/`--step-bytes` when scanning for deeper alphabetic ticker sections.

If the downloaded file uses slightly different column names, inspect the CSV header and adjust the column flags.

## Normalized news schema

All historical news datasets should be converted into this schema before modeling:

```csv
ticker,published_date,title,summary,source,url
AAPL,2024-01-02,Apple shares rise after services growth,Analysts noted stronger demand,kaggle,
```

Required columns:

- `ticker`
- `published_date`
- `title`

Optional columns:

- `summary`
- `source`
- `url`

## Importing an arbitrary historical news CSV

Use `prepare-historical-news` for large provider/Kaggle/manual CSVs because it can stream chunks, filter tickers, and cap rows:

```bash
py -m trading_sentiment.cli prepare-historical-news \
  --input downloads/historical_news.csv \
  --output data/raw/news.csv \
  --ticker-column symbol \
  --date-column published_at \
  --title-column headline \
  --summary-column body \
  --source-column publisher \
  --url-column url \
  --source-name kaggle \
  --tickers AAPL,MSFT,NVDA,AMD,GOOGL,META,TSLA \
  --chunk-size 100000 \
  --max-rows 50000
```

Use `import-news-csv` for smaller CSVs when loading the entire file in memory is fine:

```bash
py -m trading_sentiment.cli import-news-csv \
  --input downloads/historical_news.csv \
  --output data/raw/news.csv \
  --ticker-column ticker \
  --date-column date \
  --title-column title \
  --summary-column summary \
  --source-name kaggle
```

If the source file has different names, map them explicitly:

```bash
py -m trading_sentiment.cli import-news-csv \
  --input downloads/historical_news.csv \
  --output data/raw/news.csv \
  --ticker-column symbol \
  --date-column published_at \
  --title-column headline \
  --summary-column body \
  --source-column publisher \
  --url-column url \
  --source-name kaggle \
  --tickers AAPL,MSFT,NVDA,AMD,GOOGL,META,TSLA
```

Then continue the pipeline:

```bash
py -m trading_sentiment.cli fetch-prices --tickers AAPL,MSFT,NVDA,AMD,GOOGL,META,TSLA --start 2023-01-01 --end 2024-12-31 --output data/raw/prices.csv
py -m trading_sentiment.cli build-dataset --news data/raw/news.csv --prices data/raw/prices.csv --output data/processed/modeling_dataset.csv
py -m trading_sentiment.cli train-baseline --dataset data/processed/modeling_dataset.csv --metrics-output reports/baseline_metrics.json --predictions-output reports/baseline_predictions.csv
py -m trading_sentiment.cli backtest-predictions --predictions reports/baseline_predictions.csv --summary-output reports/backtest_summary.csv --trades-output reports/backtest_trades.csv --equity-output reports/backtest_equity_curve.csv
```

## Dataset quality checklist

Before using a dataset for project claims, verify:

- The license permits educational/portfolio use.
- Dates are article publication dates, not scrape dates.
- Tickers are specific to the article or source row.
- Rows cover enough time for train/test/backtest splits.
- News timestamps do not leak post-market information into same-day decisions.
- Price data covers the same ticker/date range as the news data.
